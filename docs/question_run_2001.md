# 질문 30개 실행 결과 (2001년 그래프, 2층)

[질문 30개](questions_b_2001.md)를 본 그래프(`enron/output`)에 한 번씩 돌린 기준선 결과다. 2층까지의 보고서를 전부 읽는 방식이고, 아직 가지치기나 조기 종료는 적용하지 않았다.
2026-11-24에 [run_questions.py](../run_questions.py)로 돌렸다. 응답 분류는 응답 문장을 읽고 나눈 1차 분류이고, 정답과 대조하는 채점은 아직 하지 않았다.

## 한눈에 보기

- 30문항을 32분에 돌렸다. LLM 호출 8,307회가 전부 성공했고 실패나 재시도는 없었다.
- 비용은 OpenAI 콘솔 기준으로 이번 실행분이 약 3.4달러, 질문당 평균 약 0.11달러다. 토큰으로 계산한 약 12달러의 3분의 1이다. 프롬프트 캐시 때문으로 보이지만 확인이 필요하다.
- 내용이 아예 없는 답이 5개(Q02·Q05·Q06·Q08·Q10), 정답 수치는 적었지만 순위 확정을 거부한 답이 3개(Q01·Q04·Q09), 일부만 답한 것이 1개(Q03), 답이 나온 것이 1개(Q07)다. 모두 "상위 몇 개" 유형이다.
- "전부 나열"과 "추세" 20문항은 모두 내용이 있는 답이 나왔다. 다만 일부 항목은 응답이 "확인 불가"라고 밝혔다.
- 한 번만 나오는 구체적인 수치는 보고서에 남지 않는 경향이 보인다.

## 2. 호출, 토큰, 시간, 비용

| 항목 | 값 |
|---|---|
| 걸린 시간 | 32분. 질문당 평균 64초 (38 ~ 105초). 유형별 평균은 상위 몇 개 55초, 전부 나열 56초, 추세 80초 |
| LLM 호출 | 8,307회, 전부 성공. 질문당 map 276회와 reduce 1회 (정형 문장이 나온 3문항은 reduce가 없다) |
| 토큰 (`query.log` 실측) | 입력 104,957,478 + 출력 3,271,332 = 108,228,810. 질문당 평균 약 361만 |
| 비용 (OpenAI 콘솔) | 오늘 누적 3.87달러. 이번 실행분은 약 3.4달러, 질문당 평균 약 0.11달러 |

- 이번 실행분은 오늘 누적 3.87달러에서 실행 전 사용분 약 0.43달러(질문 4번 0.4달러, 시험 호출 3번 약 0.03달러)를 뺀 값이다. 콘솔 금액이 반올림이라 ±0.1달러쯤 오차가 있다.
- 토큰에 단독 실행 단가(100만 토큰당 약 0.108달러)를 곱하면 약 12달러인데 실제는 그 3분의 1이다. 이 단가는 질문 4번(대부분 2층 질문 1개, 371만 토큰)에 콘솔 누적 0.4달러가 찍힌 값으로 구했다.
- 가장 그럴듯한 원인은 OpenAI의 프롬프트 캐시다. map 호출의 시스템 메시지(지시문과 보고서 묶음)가 질문이 달라도 묶음마다 같아서, 두 번째 질문부터는 입력 대부분이 캐시 가격으로 계산됐을 수 있다. 입력의 약 94%가 캐시되고 캐시 입력이 90% 할인이며 출력 단가가 입력의 5 ~ 8배라고 가정하면 3.3 ~ 4.1달러가 되어 실제와 비슷하다. **확인하려면 콘솔 사용량의 cached 입력 토큰 수를 본다(약 1억이면 맞다).** 대시보드 반영이 늦었을 가능성도 남아 있다.
- `run_questions.py`가 화면에 찍은 금액(11.3달러)은 map 단계 토큰에 같은 단독 실행 단가를 곱한 값이라 캐시를 반영하지 않는다. 토큰 수 자체는 실제보다 약 3% 낮다.

본 구축 문서의 질문 비용 예상과 비교하면 다음과 같다.

| 읽는 층 | 보고서 | map 호출 (예상 → 실측) | 질문 하나 (예상 → 실측) |
|---|---|---|---|
| 0층까지 | 80개 | 6개 안팎 → 7 | 1센트 안팎 → 1센트 이하로 추정 (5 ~ 16초) |
| 1층까지 | 743개 | 약 65 → 미측정 | 약 0.09달러 → 미측정 |
| 2층까지 | 4,036개 | 약 280 → 276 | 약 0.4달러 → 단독 실행 약 0.37달러, 30문항 연속 실행 평균 약 0.11달러 (64초) |

## 4. 답이 없는 이유

정답에 필요한 사실이 보고서(`full_content`)에 있는지 파일로 확인했다.

| 분류 | 문항 | 확인한 것 |
|---|---|---|
| 사실이 보고서에 없다 | Q05, Q10 | 정답 수치가 어느 층 보고서에도 없다 |
| | Q02, Q06 | 주제는 나오지만 정답의 수치(미성사 건수, MW당 단가)가 없다 |
| | Q08 | 2층 이하에는 없고 3층 보고서 1개에 일부(81,398 MW)만 있다 |
| 사실은 있으나 조건을 확인하지 못해 확정 거부 | Q01, Q04, Q09 | 수치가 2층 이하 보고서에 있다. 공통 지시문이 날짜·발신 기준 범위를 지키라고 하는데, 보고서에 해당 대화의 날짜·발신 정보가 없어 순위를 확정하지 못했다 |

- 정답 문서가 "서로 다른 메일에 나온 정보를 결합"한다고 한 Q01·Q02·Q04·Q08·Q09는 5개 모두 답이 안 나왔다. "한 메일 안의 후보 비교"인 Q03·Q05·Q06·Q10도 모두 실패하거나 일부만 답했다.
- 관찰: 성공한 Q07의 엔론 65%는 2층 이하 보고서 13개에 나온다. 반면 Q05의 수치는 0개이고 Q01의 1,080 MW는 3개다. 반복되거나 중심이 되는 사실은 보고서에 남고, 한 메일에만 나오는 숫자는 사라지는 것으로 보인다. 검증한 것은 아니다.

## 6. 실험에 영향을 주는 점

1. **답이 없어도 비용은 같다.** 정형 문장이 나온 Q02·Q06·Q10도 map 호출 276회, 입력 약 343만 토큰을 다른 문항과 똑같이 썼다. 조기 종료로 아낄 여지가 가장 큰 곳일 수 있으나, 확인한 것은 아니다.
2. **"답 없음"이 두 모양으로 나온다.** 공통 지시문이 "근거를 찾을 수 없는 항목은 확인 불가라고 적어라"고 해서, Q05·Q08은 정형 문장 대신 "근거 없음" 문장이 점수 100짜리 핵심 문장이 되어 reduce로 넘어갔다. "점수 붙은 핵심 문장이 나왔는가"를 조기 종료 신호로 쓰려면 이 둘을 구분해야 한다. `--plain`(질문만 전송)으로 비교해 볼 수 있다. 2026-11-25에 이 문장을 공통 지시문에서 뺐다.
3. **reduce가 핵심 문장을 잘라 낸다.** reduce는 점수가 높은 문장부터 약 12,000토큰까지만 받는다. 추세 문항 중 Q21·Q22·Q24·Q25·Q27·Q30은 핵심 문장이 158 ~ 510개라 약 110 ~ 117개만 들어갔다(토큰은 근사). 같은 점수 안에서는 순서대로 잘리는데, Q24(6월 25일 협상 개시)와 Q25(7월 FERC의 단일 RTO 명령)는 잘린 문장에 응답이 "확인되지 않는다"고 한 사실이 들어 있었다. 나머지 4개 문항은 확인한 범위에서 영향이 뚜렷하지 않았다. 채점할 때 "map 단계가 놓친 것"과 "reduce 단계에서 버려진 것"을 구분해야 한다. 잘린 문장도 문항별 기록의 `key_points`에 남아 있다.
4. **같은 질문을 다시 돌려도 결과가 같다고 보장할 수 없다.** 이번 결과는 한 번의 실행이다. 반복 실행 간 변동은 재 보지 않았다.
5. **달러 비용은 캐시에 따라 달라질 수 있다.** 캐시 가설이 맞다면 같은 보고서 묶음을 연속으로 돌릴수록 싸진다. 가지치기 전후를 달러로 비교하면 실행 순서와 간격이 결과에 섞이므로, 비용은 호출 수와 토큰 수(캐시된 입력 구분 포함)로 비교한다.

## 7. 결과 파일과 재실행

결과는 `results/20261124-131354_L2/`(4.7MB)에 있다.

| 파일 | 내용 |
|---|---|
| `answers.md` | 읽기용 기록. 문항별 질문, 응답, 인용한 보고서(번호, 층, 제목), 정답(채점 기준) |
| `summary.csv` | 문항별 한 줄 요약 (상태, 인용 보고서, 토큰, 시간, 실패한 묶음 수) |
| `records/Q01.json` ... | 문항별 전체 기록. 실제로 보낸 프롬프트, 응답, 묶음별 보고서 번호, 점수가 붙은 핵심 문장 |
| `run.json` | 실행 조건과 합계 |

```
python run_questions.py --dry-run                          # 호출 없이 계획과 예상 비용
python run_questions.py                                    # 30문항 전부, 2층 (이번 실제 약 3.4달러)
python run_questions.py --only Q03 Q05 --level 0           # 일부만, 0층으로
python run_questions.py --out results/20261124-131354_L2   # 중단된 실행을 이어서
```

정확한 토큰은 실행이 끝날 때 `enron/logs/query.log` 끝에 남는 합계 블록에서 본다.

## 8. 아직 하지 않은 것

- 정답과 대조하는 채점. 값은 맞고 순위나 조건이 빠진 답(Q01·Q04·Q09)을 몇 점으로 칠지 채점 전에 정한다.
- 문항별 라벨(유형, 답이 없는 이유). 가지치기 결과를 보기 전에 확정해야 한다.
- 1층 비용 측정 (질문 하나, 약 0.1달러 예상).
- 콘솔 사용량의 cached 입력 토큰 수로 캐시 가설 확인. 맞다면 실험의 비용 비교는 토큰 수로 한다.
- 지시문을 붙이는 경우와 질문만 보내는 경우(`--plain`)의 비교.
- 반복 실행 간 변동 확인.
- `results/`를 저장소에 올릴지 정하기.
