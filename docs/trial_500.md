# 500통 시험 구축에서 결정된 것

500통으로 그래프를 두 번 구축해 보고 정한 전처리 기준과 설정을 정리한다.
데이터 구조와 전처리 단계별 설명은 [data.md](data.md)에 있다.

## 한눈에 보기

- 전처리 기준은 아래 표대로 정했다. 시험 구축에서 문제가 된 것은 받는 사람 명단 하나였고, 고쳤다.
- 모델은 `gpt-6-luna`와 `text-embedding-3-small`이다. 본 구축과 실험이 끝날 때까지 바꾸지 않는다.
- 500통을 구축하는 데 약 13 ~ 21분, 약 3.7달러가 든다 (추정).
- 본 구축의 규모와 메일함 구성은 아직 정하지 않았다.

## 전처리 기준

| 항목 | 정한 값 | 이유 |
|---|---|---|
| 메일함 | `dasovich-j` | 캘리포니아 전력 위기 담당자라 주제가 뚜렷하다 |
| 기간 | 2001-01-01부터 날짜순 500통 (2001-02-20까지) | 연속된 기간이라 대화가 끊기지 않는다. 시작일 자체는 임의로 잡았다 |
| 보낸 사람 | `@enron.com`만 | 광고, 뉴스레터, 메일링 리스트를 걸러 낸다 |
| 자동 발송 | 전사 공지 계정, 시스템 알림, `calendar` 등 일정 폴더 제외 | 사람이 쓴 업무 대화가 아니다 |
| 인용문·전달문 | 표시 줄부터 끝까지 삭제 | 답장마다 이전 메일이 통째로 붙어 있어 같은 내용이 반복된다 |
| 본문 길이 | 100자 이상 2만 자 이하 | 너무 짧으면 정보가 없고, 너무 길면 기사 모음이다 |
| 중복 | (보낸 사람, 날짜, 제목, 정리된 본문)이 같으면 하나만 | 같은 메일이 여러 폴더에 들어 있다 |
| 받는 사람 표기 | 본문 머리에 앞 5명만, 나머지는 `and N others` | 1차 시험에서 발견한 문제. 아래 참고 |
| 서명 제거 | 하지 않음 | 서명이 엔티티로 잡힌 경우가 1건뿐이었다 |

단계별 건수 (`dasovich-j`, 2001-01-01 이후):

| 단계 | 건수 |
|---|---|
| 메일함 전체 | 28,234 |
| 기간 안 | 18,363 |
| 사외 발신 제외 | −5,227 |
| 자동 발송·일정 폴더 제외 | −76 |
| 본문 100자 미만 제외 | −5,224 |
| 본문 2만 자 초과 제외 | −507 |
| 중복 제외 | −2,985 |
| 남은 것 | 4,344 |
| 시험 구축에 쓴 것 | 500 |

## 시험 구축에서 고친 것: 받는 사람 명단

1차에서는 본문 머리의 `To:` 줄에 받는 사람을 전부 적었다.
500통 중 137통이 받는 사람 10명 초과였고, 가장 많은 것은 212명이었다.
그 결과 그래프가 "누가 메일을 받았다"로 채워졌다.

2차에서는 앞 5명만 적고 나머지는 `and N others`로 줄였다.

| 항목 | 1차 (명단 전체) | 2차 (5명까지) |
|---|---|---|
| 엔티티 | 3,081 | 2,610 |
| 그중 사람 | 1,049 | 694 |
| 관계 | 8,880 | 5,740 |
| "메일을 받았다" 종류의 관계 | 3,557 (40%) | 904 (16%) |
| 보고서 | 694 | 646 |
| 제목이 메일·수신자인 보고서 | 66 | 32 |

2차에서 남은 32개는 엔티티 5~10개짜리 작은 커뮤니티이고, 업무 내용이 일부 섞여 있다.
`To:` 줄을 아예 빼면 "누가 누구에게"가 사라지므로 여기서 멈춘다.

## 구축 설정

| 항목 | 값 |
|---|---|
| 도구 | graphrag 3.3.0 |
| 채팅 모델 | `gpt-6-luna` |
| 임베딩 모델 | `text-embedding-3-small` |
| 조각 크기 | 1,200토큰, 겹침 100토큰 (기본값) |
| 엔티티 유형 | 조직, 사람, 장소, 사건 (기본값) |
| 커뮤니티 최대 크기 | 10 (기본값) |
| 프롬프트 | `enron/prompts`의 기본값 그대로 |

`gpt-4.1-mini`와 `gpt-5-mini`는 지원 종료가 예고되어 있어 쓰지 않았다.

## 2차 구축 결과

| 항목 | 값 |
|---|---|
| 메일 | 500통 |
| 조각 | 547개 |
| 엔티티 | 2,610개 (사건 942, 조직 738, 사람 694, 장소 236) |
| 관계 | 5,740개 |
| 커뮤니티 = 보고서 | 646개 |
| 층별 보고서 수 | 0층 32, 1층 213, 2층 342, 3층 48, 4층 4, 5층 4, 6층 3 |

보고서가 메일보다 많은 이유: 커뮤니티는 메일이 아니라 엔티티를 묶는다.
엔티티 2,610개를 10개 안팎으로 묶으면 한 층에만 수백 개가 나오고, 층마다 따로 센다.

품질: 최상위 보고서는 "캘리포니아 전력 위기: 전력회사, DWR, CPUC"이고, 하위에는 "AB1X 직접 접근과 DWR 전력 구매 정책", "수요 반응 프로그램과 AB31X" 같은 구체적 주제가 잡혔다.

알려진 작은 문제:

- `ENRON`, `ENRON CORP.`, `ENRON CORPORATION`이 서로 다른 엔티티로 잡힌다.
- "2001년 1월 24일 메일"처럼 메일 자체가 사건으로 잡힌 것이 20개쯤 있다.

## 시간과 비용

| 항목 | 1차 | 2차 |
|---|---|---|
| 걸린 시간 | 21분 | 13분 |
| 과금된 LLM 호출 | 4,336회 | 2,966회 (809회는 캐시 재사용) |
| 청구액 (OpenAI 콘솔) | 4.19달러 | 2.33달러 |

2차는 1차의 캐시를 일부 재사용해서 싸고 빨랐다.
두 청구액 모두 지금 설정으로 처음부터 구축한 값은 아니다.
1차는 받는 사람 명단을 전부 넣던 옛 설정이고, 2차는 추출 호출 1,094회 중 472회만 과금됐다.
2차에 캐시로 아낀 추출 호출을 더해 계산하면, 지금 설정으로 처음부터 구축할 때 500통당 약 3.7달러, 15~20분으로 추정한다.

청구액은 가격표 단가로 계산한 값의 약 2.1배였다 (1차 2.11배, 2차 2.14배).
모든 응답의 `service_tier`가 `fast`로 기록되어 있어, 더 비싼 우선 처리 요금이 적용된 것으로 보인다. 확인이 필요하다.

넓은 질문 2개를 2층 기준으로 돌린 비용은 합계 0.22달러였다 (질문당 0.11달러, 보고서 587개, 상자 36개, 19~29초).

graphrag 로그의 토큰 수에 가격표 단가를 곱한 값은 실제 청구액의 절반 수준이었다.
비용은 로그 계산값이 아니라 OpenAI 콘솔의 청구액으로 확인한다.

## 아직 정하지 않은 것

- 본 구축의 메일 수와 메일함 구성
- 질문 한 번에 드는 비용 (아직 재지 않았다)
- 질문 때 쓸 커뮤니티 층
